## 可复核的步骤

```text
git ls-tree -rlz f83bcb3
git rev-list --objects f83bcb3
git rev-list --objects --all
git cat-file --batch-check="%(objectname) %(objecttype) %(objectsize) %(objectsize:disk)"
git count-objects -v
gh api repos/taoduo0428/facebook-reaction-capture --jq .size
```

将 `rev-list` 每行的对象名送入 `cat-file --batch-check`，按 `objecttype=blob` 过滤后求和，再用同一行的代表路径分类。这些读取都不要求检出历史文件。

## 处置与预防

当前树清理已经降低新源码包的体积。普通克隆仍可从主分支祖先访问历史抓包、日志、备份及工具链。建议仓库所有者在受控环境核查历史数据的隐私影响，如发现有效秘密应先轮换。限制将来新增文件应检查 PR 实际新增的 blob 大小和路径分类，同时保留发布白名单，避免一次全目录镜像再次引入现场数据。

如需清除已发布历史，独立安排变更窗口，先盘点所有分支、旧标签、fork、发布物、使用者和外部缓存，再确定清理对象与迁移计划。历史重写将变更提交 ID，影响现有签名、Release 指向和所有克隆，服务商缓存及他人克隆还需单独处置。本轮保留原有公共历史、标签和 Release。
