2026-11-22 10:47 UTC，Windows 11 AMD64 开发机完成一组固定 8 秒的 k6 负载和一组临时 SQLite 基准。k6 实收 72 个读请求和 24 个提交请求，96 个响应检查全部通过，丢弃迭代数为 0。队列完成 32 个模拟任务，最终活动租约为 0。

两次测量均基于 `29b66f3a31f8d070ed89450b3b1e40fb04271367` 的 dirty 工作树。运行前后的 87 个源码文件聚合 SHA-256 均为 `faf86b469f04aa2e77dc0fcc2b6495cbc00b39a80907a8fc15cb7bbc5c1fa9d1`。聚合覆盖 backend Python 模块、perf Python/k6 工装、历史 API 和启动器入口。两次运行的命令、UTC 时间、机器、起止指纹、检查计数及原报告摘要保存在[本次 JSON](../../perf/phase_k_evidence.json)。集成后的新快照可用下文命令复测。

## HTTP

目标为 Uvicorn + 实际 FastAPI 路由 + 注入的内存 manager。读流轮询 health、latest、metrics 和一个本次生成的 job 的 progress。提交流将合成输入写入内存。每一流最多 1 个并发客户端。预定速率分别为 9 和 3 请求/秒，发送预算分别为 72 和 24 个请求。每次建立独立 HTTP 连接。k6 的请求时间包含发送、等待和接收，连接建立另计。

| 操作 | 样本 | 实测请求/秒 | p50 ms | p95 ms | p99 ms |
|---|---:|---:|---:|---:|---:|
| 读 | 72 | 9.001 | 3.954 | 11.615 | 20.915 |
| 提交 | 24 | 3.000 | 6.666 | 17.962 | 26.330 |

k6 实际时长 7.9993 秒。`http_req_failed.rate=0`，`checks.passes=96`，`checks.fails=0`，`dropped_iterations.count=0`，k6 退出码为 0。原始 `http_req_failed` 是布尔 Rate，96 个 false 表示 96 个请求未被判定为 HTTP 失败。工装还按分流核验状态码、随机服务身份和提交返回的 job ID。失败率或丢弃计数缺失时记为 `null`，此次运行标为未通过。

独立服务进程在采样窗口累计使用 **0.35938 CPU 秒**，76 个采样中的最高常驻内存为 **93,884,416 字节**。CPU 秒统计系统和用户态时间。RSS 是抽样观测峰值，采不到的资源字段保留 `null`。

## SQLite、租约与合成文件

临时文件型 SQLite 启用 WAL、外键和 `synchronous=NORMAL`，实读 `busy_timeout=30000 ms`。两个写线程在每轮屏障同时起步。32 次独立写事务后，8 次全表读取均校验了 32 个不同 ID。队列使用带时间戳的 MockExecutor、单个合成设备及单 active worker。表中的队列延迟为预先入队至执行器开始，吞吐为已持久化完成数除以调度时间。

| 操作 | 样本或核验结果 | 吞吐 | p50 / p95 / p99（ms） |
|---|---|---:|---:|
| 双写者提交 | 32 笔 | 152.072 笔/秒 | 6.052 / 16.013 / 25.160 |
| 全表读取 | 8 次，每次 32 行 | 413.657 次/秒 | 1.835 / 6.468 / 6.468 |
| 队列 | 完成 32/32，剩余租约 0 | 85.71 个任务/秒 | 225.595 / 350.226 / 371.627 |
| 两请求争用同一租约 | 12 轮，每轮 1 个获准 | — | 6.251 / 15.904 / 15.904 |
| 同轮未获准的请求 | 12 个 | — | 16.023 / 21.344 / 21.344 |

哈希走本快照离线导入器的 `_collect_artifacts`，耗时包括目录与文件状态检查。文件由已知字节生成并重复读取，结果包含操作系统缓存效应。整个状态工装累计 **0.95312 CPU 秒**，13 个采样中的最高 RSS 为 **60,424,192 字节**。12 次恢复使用合成进程状态，逐轮从已提交的数据库重读租约和终态。

## 复测

在项目根目录的 PowerShell 中执行下列命令。`$py` 指向已装项目依赖的解释器。本次只读使用相邻项目既有 venv。将 `$env:K6_BIN` 指向解压后的便携二进制，无需设置系统 PATH。Windows amd64 官方 v0.54.0 ZIP 的 SHA-256 实测为 `b1b1221c31b82f81b95f67c0041c8067c9cf49017b0eb05ecaafd05f330a2dac`，已对照[官方校验清单](https://github.com/grafana/k6/releases/download/v0.54.0/k6-v0.54.0-checksums.txt)。

```powershell
$py = '..\facebook\.venv\Scripts\python.exe'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:K6_BIN = 'C:\path\to\k6.exe'
& $py -B -m perf.run_api_load --driver k6
& $py -B -m perf.state_bench
& $py -B -m unittest discover -s tests -p test_backend_perf_harness.py -v
```

每次测量生成独立时间戳的 `perf/results/phase_k_*.json`。HTTP 父进程绑定并持有 `127.0.0.1:0` 的套接字，把套接字交给本次子服务。父子进程使用随机请求密钥和独立的预期响应身份做握手，每个负载响应再次检查身份。k6 的私有临时配置固定目标、时长、发包预算和并发，禁用重定向、代理环境继承与使用报告。独立运行仓库里的 JS 会在初始化阶段退出。缺少 k6 时可显式选 `--driver python`，报告记录所用驱动。

本次机器为 Windows 11 build 26200、20 个逻辑处理器，Python 3.13.12、SQLite 3.50.4、FastAPI 0.121.2、Uvicorn 0.41.0、SQLAlchemy 2.0.44、k6 v0.54.0。样本反映固定低负载和很小的临时库。衡量系统容量上限、真实采集耗时、长期尾延迟或跨平台表现需要相应的独立数据。定向回归运行了 15 项，其中 14 项通过，1 项为 Windows 上跳过的 POSIX 专属采样器测试。
