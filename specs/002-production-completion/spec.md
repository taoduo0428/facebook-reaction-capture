# v1.1 生产运行时增量规格

基线为 `main@f83bcb3`。验收对象是本地单进程 API、持久任务、单活设备与既有产物语义。真实账号、模拟器与历史运行数据由操作者管理。本开发树上的故障注入使用临时目录与自建的子进程。

## 所有权与兼容

FastAPI lifespan 管理串行协调器的启动、排空和退出。任务与批次的受理点是持久事务提交。领取、设备占用、尝试编号与对应事件需要一致的提交边界。派发前检查上一执行者的进程身份与传输清理证据。结果写入失败要保留诊断，所有观察者在提交后才能读取新状态。对已有设备限制保留设备绑定。确认完成仍以现有业务验证器为准。文件摘要单独表示文件字节的身份。

旧 HTTP 响应与命名保持兼容。单个新任务和批次分别使用现有的 HTTP 契约。旧安装切换数据库需要离线核对完整记录，回退通过备份与独立导出目录演练。新安装单进程、同一文件型 SQLite 库、每事务独立 Session。历史版本与标签保留原样。

## 实施与验收任务

| 范围 | 可执行验收 |
|---|---|
| A/B，基线、版本与仓库 | 实际源码追线、Git 元数据审查、全量基线、包/API/README/标签校验，源码 ZIP 包含当前发布说明 |
| C，存储切换 | 拒绝不完整迁移，批次原子写入，重启从所属 store 验证，导入幂等、回退可核对，失败无半提交 |
| D/E，单活协调 | 正常应用工厂的提交→领取→执行→验证→结果链，默认并发 1，关闭、冲突、取消和 failover 的负路径 |
| F，进程 | 自建子进程、出生时间、权限失败、PID 复用、进程组，Windows 与 macOS 独立验证 |
| G/H/I，观测、产物、事件 | 真实生产路径上的上下文传播、敏感字段处理、状态与事件原子提交、流式哈希与变更检测 |
| J/K，功能和容量 | HTTP 字节对比、全量 unittest、SQLite 争用、API/调度/哈希独立计量，标明样本及限制 |
| L/M，部署与发布 | 原生和容器启动/关闭/重启、schema 演进、双平台 CI 与最终 Release 版本一致 |
| N/O，现场验收与架构复核 | 记录 Windows/macOS 设备验收状态，逐图追踪调用点，核对剩余风险和上线条件 |

变更按可回滚的小提交推进。在迁移和设备租约的门禁测试通过前保持当前运行时选择。任何回退先停服务并保全状态，避免让两个版本同时拥有同一设备。每轮结果存于开发分支提交和对应测试，最终报告按 A–I 给出。
